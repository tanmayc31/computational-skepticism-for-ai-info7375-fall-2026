## What I'd tell myself next time
- Save raw traces when I find a failure. My best evidence (the 0.547 Camry chunk) exists only as a number in a report because I never saved the trace. Veracite's design depends on recorded traces, and this is exactly why.
- Decide "pitch or build" first. I lost time testing old code before re-reading that nothing had to exist yet.
- Read the toolkit's defaults against the assignment's rules before running it. The persona conflict was predictable from the skill file.
- Check an AI's numbers against a clock or a file, not against its confidence. Its timestamps, its render estimates and one code comment in the toolkit were all confidently wrong.
- Watch the film myself. My own viewing caught the one-box-for-three-skills mismatch; no gate checks whether the picture matches the words.
